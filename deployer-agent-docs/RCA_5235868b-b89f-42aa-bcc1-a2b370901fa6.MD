# RCA — Deploy run 5235868b-b89f-42aa-bcc1-a2b370901fa6 (build_image failure)

## Symptom
Redeploy of `sl-launchers-ai` failed at the **build_image** step. Cloud Build error:

```
error during build:
Build failed with 1 error:
TypeError: manualChunks is not a function
    at name (.../node_modules/rolldown/dist/shared/create-bundler-option-BDjYxIaE.mjs:2051:11)
error Command failed with exit code 1.
```

The frontend compile (`vite build`) crashed; no image was produced. The previous run (0b189aa6, currently live) is unaffected and still serving.

## Root cause (CONFIRMED + reproduced)
`frontend/vite.config.js` configures `build.rollupOptions.output.manualChunks` as an **object**:

```js
build: {
  minify: "esbuild",
  cssMinify: true,
  rollupOptions: {
    output: {
      manualChunks: {
        vendor: ["react", "react-dom", "react-router-dom", "framer-motion"],
      },
    },
  },
},
```

The frontend now builds with **Vite 8** (`"vite": "^8.3.6"` in `frontend/package.json`), which uses the **rolldown** bundler. rolldown does **not** support the object form of `manualChunks` — it only accepts a **function** (or the newer `output.advancedChunks`). When it receives the object it tries to invoke it as a function and throws `manualChunks is not a function`. This is Rollup→rolldown behavior that changed with the CRA/craco → Vite 8 migration; the old object-style `manualChunks` was carried over unchanged.

## Evidence (reproduced in sandbox)
Isolated repro with the exact prod toolchain (vite@8.3.7, rolldown@1.2.18, @vitejs/plugin-react@6):
- **Object form** (current source) → fails with the identical `TypeError: manualChunks is not a function`, exit 1.
- **Function form** → `✓ built` successfully.
- **manualChunks removed** → `✓ built` successfully.

## Fix (E1 / source change required)
Edit `frontend/vite.config.js`. Either option works:

**Option A — convert to a function (preserves vendor chunking):**
```js
build: {
  minify: "esbuild",
  cssMinify: true,
  rollupOptions: {
    output: {
      manualChunks(id) {
        if (id.includes("node_modules")) {
          if (/[\\/]node_modules[\\/](react|react-dom|react-router-dom|framer-motion)[\\/]/.test(id)) {
            return "vendor";
          }
        }
      },
    },
  },
},
```

**Option B — simplest: drop the `manualChunks` config** and let Vite/rolldown handle chunking by default:
```js
build: {
  minify: "esbuild",
  cssMinify: true,
},
```

After E1 applies either change, re-trigger the deploy. No manifest, secret, tier, or infra change is needed. The Google Search Console meta-tag change and the rest of the Vite migration are otherwise fine — this one config line is the only blocker.
